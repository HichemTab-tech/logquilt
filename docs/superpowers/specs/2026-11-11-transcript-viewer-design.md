# Claude Code transcript viewer

Build a local website that replays Claude Code JSONL in its CLI visual language: full-width monospace text, dark background, orange identity, user chevrons, assistant bullets, indented tool results, diffs, thinking, and compaction separators. The supplied 56 MB session contains ten compactions and is the acceptance dataset. The user prioritizes fidelity over a conventional chat website.

Approaches considered: embedding a live Claude process would risk executing commands and would not provide an independent archive; a canvas terminal would hinder searching and expanding records; a browser transcript renderer supports archive navigation and readable selectable text. The implementation choice is a React/Vite renderer, a parsing worker, and a virtual list. This is an implementation decision, not an assertion of pixel identity. JSONL does not store terminal dimensions, original font/colors, animation, or lost pre-compaction text.

The user confirmed normal CLI mode, with tool output collapsed, then explicitly narrowed the scope to viewing and scrolling only. The loaded conversation has no shortcuts, search, menus, buttons, tool expansion, theme controls, or active links. Use dark styling and the local JetBrains Mono font. Show the normal tool previews, static diffs, image placeholders, and compaction boundaries. Keep a file picker only in the empty state and accept dropped files. Never execute commands or fetch embedded URLs/images. Suppress bookkeeping and API payload duplicates. Show malformed-line diagnostics without dumping their contents.

Load supplied data from its original file through an explicit localhost-only server argument. Do not copy it into source, fixtures, screenshots, or build output. Files selected in the browser stay in browser memory. No remote publication is authorized. Test with synthetic fixtures, then verify counts and browser behavior against the original file without printing conversation content.
